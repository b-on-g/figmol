# Figmol

Конструктор сайтов на канвасе: собираешь страницу из блоков, по кнопке получаешь
живой сайт на GitHub Pages и полноценный $mol-проект в своём репозитории.
План и продуктовые решения — в [PLAN.md](./PLAN.md).

## Структура

```
schema/    Giper Baza entities: home, site, page, node
store/     чтение и запись документа; общий для канваса, панелей и инспектора
blocks/    реестр: размеры и пресеты kind'ов, шаблоны секций — чистые данные
magnet/    геометрия прилипания и расстояний между боксами — без DOM и стора
app/       редактор
  start/     экран «сайта ещё нет» с кнопкой создания
  tools/     палитра примитивов (иконки слева)
  side/      левая панель редактора
  pages/     список страниц, название и адрес текущей, удаление
  blocks/    палитра блоков builderui и секций-шаблонов
  layers/    дерево нод текущей страницы
  row/       строка списка боковой панели (общая для страниц и слоёв)
  canvas/    канвас: pan, zoom, выделение (в том числе рамкой), drag, resize, drop в контейнеры
    shape/     один элемент на листе (и шейпы его детей)
  inspector/ панель свойств выделенного элемента
    field/     строка «подпись — контрол»
    number/    числовое поле без степперов
gen/       генератор MAM-проекта из снимка сайта
  snap/      снимок дерева из Базы в обычный JSON
deploy/    публикация на GitHub
  github/    клиент REST API: репозиторий, коммит, Pages, статус сборки
  publish/   панель «Опубликовать» с журналом шагов
mine/      своя IndexedDB + фолбэк мастеров (нужен на общем localhost-origin)
```

## Как устроено

В домашнем Land'е пользователя лежит только ссылка на сайт, а сам сайт — корневая
пешка отдельного Land'а. Так проект можно будет отдать по ссылке, не отдавая
аккаунт. Страницы и все ноды живут пешками внутри этого же Land'а: открыть проект
стоит один синк.

Land под сайт захватывается по кнопке на стартовом экране, а не сам собой:
`land_grab` считает Proof-of-Work, и задача с этим расчётом кешируется фиброй,
которая её запросила. Нажатие кнопки — одна такая фибра, она переживает
приостановки Базы. Тот же вызов из рендера начинал бы расчёт заново на каждом
ретрае.

Фрейм с непустым `Direction` — это flex-контейнер: дети раскладываются потоком, их
X и Y не значат ничего, а драг внутри такого фрейма меняет порядок в `Kids`.
Куда попадёт элемент, решает самый глубокий фрейм под курсором; координаты при
переносе пересчитываются от замеров DOM, а не от сохранённых X/Y — внутри
авто-раскладки эти два ответа расходятся.

Геометрия нод хранится в пикселях листа. Панорама и зум — свойство вьюпорта, они
накладываются одним CSS-трансформом на `World` и в Базу не пишутся.

Во время перетаскивания живой прямоугольник лежит в атоме `draft`, а в Базу
уходит один раз на `pointerup`. Иначе один драг превратился бы в сотни CRDT-юнитов.

Блоки `bui_*` рисуются настоящими компонентами `bog/builderui` — тем же кодом,
который получит опубликованный сайт. Клики по ним гасятся стилями: на канвасе
важно выделить блок, а не пользоваться им. Исключение — `bui_card`, он держит
внутри чужие ноды, и им клики нужны.

Секция — не отдельный kind, а фабрика: клик в палитре пишет в Базу готовое
поддерево из обычных фреймов, текстов, кнопок и `bui_*`. Поэтому секцию можно
разобрать теми же инструментами и генератору про неё знать нечего.

Палитра builderui по умолчанию тёмная, а лист — это страница сайта. Атрибуты
`bog_builderui_base` / `bog_builderui_lights` висят на `Sheet` канваса, и ровно
их же генератор ставит на корень собранного проекта — иначе редактор и сайт
разошлись бы в цвете.

## Публикация

Кнопка «Опубликовать» в шапке отдаёт правую панель (вместо инспектора)
`$bog_figmol_deploy_publish`. Файлы для неё считает `publish_files()` в
`app.view.ts`: снимок сайта из Базы → `$bog_figmol_gen.files()`. Имя репозитория
и имя модуля в исходниках — одно и то же `publish_name`, иначе собранный бандл
уедет мимо страницы, которая его ищет. Первое открытие панели подставляет имя из
заголовка сайта, дальше оно принадлежит пользователю.

## Владелец: аккаунт или организация

Селект «Владелец» появляется вместе с аккаунтом: личный логин первым, дальше
организации из `GET /user/orgs`. Личный аккаунт — дефолт, выбор лежит в
`$mol_state_local` и переживает перезагрузку; выход из аккаунта его забывает
вместе с токеном.

Владелец решает всё остальное: репозиторий создаётся через `POST /user/repos`
или `POST /orgs/{org}/repos`, проверка «а такой уже есть» идёт в
`/repos/{owner}/{name}`, и сайт оказывается на `https://<owner>.github.io/<name>/` —
у организации домен свой, но правило то же самое. Подсказка под полем имени
показывает готовый адрес, а не формулу.

Запомненную организацию сбрасывает на личный аккаунт только известный список,
в котором её нет — например, после входа под другим логином. Токен, которому
GitHub не даёт читать организации, молчит о них, и молчание за отказ не
считается: иначе публикация ушла бы на личный аккаунт за спиной у того, кто
выбрал другое.

Отказ создать репозиторий в организации приходит одним и тем же 403 и на «членам
нельзя создавать репозитории», и на «OAuth App здесь не одобрен». Формулировку
GitHub панель показывает как есть и дописывает к ней адрес страницы, где это
чинится: `github.com/organizations/<org>/settings/oauth_application_policy`.

## Вход через GitHub

Кнопка «Войти через GitHub» уводит на экран согласия с `client_id` OAuth App и
`redirect_uri = origin + pathname` текущей страницы. Секрет живёт в прокси
(`server/`), он же меняет код на токен; браузер сам этого сделать не может.

Скоупы — `repo workflow read:org`. Последний нужен ради списка организаций:
без него член приватной организации увидит в селекте одного себя. Токены,
выданные до его появления, продолжают работать, но организаций не покажут —
GitHub допросит недостающее на следующем входе, так что после выхода и
повторного входа список наполнится.

Одноразовый `state` пишется в `$mol_state_local` до ухода со страницы — вернуться
он должен ровно тем же, иначе чужой код не примут. Обратно приложение ловит код в
`auto()` (`app.view.ts`), обычным полем-флагом, а не атомом: `auto` — часть
мемоизированного рендера и перезапускается, а код одноразовый. Дальше открывается
панель, и обмен делает она — токен её хозяйство, и отказ ей есть где показать.

Адрес чистится через `$mol_state_arg.href()`, а не мимо него: `$mol_state_arg`
копирует адрес целиком в каждую ссылку приложения, так что `replaceState` за его
спиной продолжал бы раздавать потраченный код. Фрагмент `#!…` при этом целый.

Обмен кода — `@$mol_action` внутри отсоединённой фибры. Это не украшение: фибра
перезапускается на каждом ожидании сети, и кешированный ответ экшена — то, что не
даёт потратить одноразовый код второй раз.

На localhost вход не пройдёт: callback у OAuth App один и указывает на прод. Там
остаётся токен руками — свёрнутая складка «или вставить токен вручную». Складка
не прячется, когда токен появился: поле пишет на каждое нажатие, и секция,
пересобранная вокруг него, унесла бы поле после первой же буквы.

## Шаринг по ссылке

Сайт — корневая пешка своего Land'а с пресетом `[[null, rank_read]]`, поэтому
ссылка на Land и есть весь механизм: выдавать и мигрировать нечего. Адрес вида
`#!site=<land>` (кнопка «Поделиться» кладёт его в буфер) заставляет
`store.site()` читать этот Land напрямую, минуя домашнюю запись.

Может ли этот браузер писать, решает `store.writable()`: ранг своего ключа в
Land'е сайта. Чтение `Title()` там обязательно — права приезжают Gift-юнитами
вместе с данными, и без чтения данных Land просто не синкается.

Пока прав нет, редактор показывает сайт целиком, но без единого контрола,
который бы не сработал: нет палитры примитивов, нет блоков, нет полей страницы,
нет инспектора, ручки ресайза не рисуются, драг только панорамирует. Выделение
работает — по нему смотрят слои. В шапке плашка «только чтение» и ссылка «Мой
редактор» (`arg * site null`).

Совместного редактирования нет: чужой ключ ранга `post` в Land не выдаётся.
Кнопка «сделать копию себе» — TODO.

## Undo

Журнал живёт в `store`: список пар замыканий «как отменить / как повторить».
Все правки и так идут через `*_edit`-методы стора, так что описание шага назад —
это просто значение, которое там было. Глубина 100.

Журнал намеренно нереактивный: сеттер поля — это тело `@$mol_mem_key`, и запись
в атом изнутри другого атома открывает цикл инвалидации. История — свойство
сессии, а не документа, и читают её только два хоткея.

Правки одного поля подряд склеиваются по тегу (900 мс): набранное слово — один
шаг назад, а не шаг на букву. Пустой тег не склеивается никогда — два драга
подряд остаются двумя жестами.

Удаление ноды или страницы только отцепляет ссылку (База append-only), поэтому
отмена удаления просто возвращает ссылку на прежнее место — поддерево живо.

Один жест — один шаг назад: `store.group()` сворачивает все записи задачи в одну
запись журнала. Удалить пятерых, продублировать выделенное, подвинуть группу
стрелками — это по одному Ctrl+Z, а не по пять. Свои записи группа считает
счётчиком, а не индексом: за длинную сессию журнал успевает подрезать себе хвост
и индексы уезжают.

## Выделение и жесты мыши

Выделение — список, а не одна ссылка. Живёт оно в `app`, и туда же смотрят все
панели: `selected` — это последний элемент списка, и запись в него значит
«только этот». Так инспектор, слои и палитра продолжают работать с одной
ссылкой, а знать про несколько нужно только канвасу — единственному, кто пишет
`selection` целиком.

- обычный клик выбирает верхний элемент того уровня, который сейчас
  редактируется: клик по подписи внутри карточки выделяет карточку;
- `⌘`/`Ctrl` + клик — сразу самую глубокую ноду под курсором;
- двойной клик проваливается на уровень внутрь фрейма под курсором (`scope`
  канваса), а двойной клик по тексту или кнопке, которая уже выделена, открывает
  подпись для набора прямо на листе;
- клик мимо текущего фрейма из него выходит;
- `Shift` + клик добавляет и убирает элемент из выделения;
- драг по пустому месту тянет рамку выделения, `Shift` — добавляет пойманное к
  уже выделенному. Рамка ловит детей текущего уровня и меряет их по DOM: внутри
  авто-раскладки сохранённые X и Y ничего не значат.

Панорама переехала на средний клик и `Пробел` + драг: обычный драг по пустому
листу теперь тянет рамку. У гостя (чужой сайт по ссылке) выделять нечего, так
что для него драг по пустому по-прежнему панорамирует.

Драг двигает всё выделенное. Одиночный элемент по-прежнему ищет фрейм под
курсором и падает в него; группа только двигается — у каждой ноды свой родитель,
и «уронить это всё вон в тот фрейм» — отдельное решение, а не побочный эффект.
Нажатие на элемент группы группу сохраняет (иначе её нечем таскать), а если
нажатие оказалось кликом без сдвига — выделение схлопывается до него.

`Alt` + драг утаскивает копию: поддеревья дублируются тем же `node_copy`, что и
`⌘D`, и сразу кладутся в `draft` на прямоугольники оригиналов — иначе копия
прыгнула бы на 24 px, которыми `node_copy` разводит дубликат с оригиналом.

Ручки ресайза — четыре угловые и четыре рёберные (`n`/`s`/`w`/`e`), и рисуются
они только когда выделен ровно один элемент. Вокруг нескольких рисуется общая
рамка с четырьмя угловыми ручками, и тянут они всю компоновку целиком: каждый
элемент сохраняет своё место и свой размер как долю от этой рамки. Противоположный
ручке угол стоит на месте, всё вместе — один шаг назад. Ноды внутри авто-раскладки
в такое масштабирование не попадают: их размещает фрейм, и записанные координаты
он бы всё равно перебил.

Текущий фрейм (`scope`) — обычное поле класса, а не `@$mol_mem`, как и остальное
состояние жеста. Его никто не рисует, значит единственный подписчик ячейки — фибра
обработчика, а её убивает следующее событие: ячейка при этом сбрасывается в
дефолт, и двойной клик «проваливался» ровно на один клик. Симптом был красивый —
клик после двойного возвращал выделение на верхний уровень.

Замеры по DOM делятся на `zoom_live()` — масштаб, который реально нарисован
(ширина листа / `sheet_width`), а не на атом `zoom`: запись в атом доезжает до
экрана кадром позже, и `⇧1` сразу после `⌘0` мерил бы содержимое против ещё не
применённого трансформа.

## Прилипание, направляющие и расстояния

Драг и ресайз прилипают к соседям того уровня, на котором идут, и к рамке вокруг
них — к листу или к фрейму, внутри которого всё происходит. Считается это
`bog/figmol/magnet/`: чистая геометрия без DOM, стора и зума, поэтому проверяется
тестами, а не глазами.

Кандидатов даёт каждый сосед: два края и середина по каждой оси. Пробников у
перетаскиваемого бокса столько же — левый край, правый край, центр, — и ищется
пара «пробник — линия» с наименьшим расстоянием, но не дальше 6 экранных пикселей
(порог делится на `zoom_live()`, потому что это про меткость руки, а не про
масштаб). Пробники перебираются краями вперёд: при равном расстоянии выигрывает
край, встать вплотную к соседу — намерение более вероятное, чем случайно совпасть
центрами. Ресайз пробует только те края, которые тянет ручка; прилипание, после
которого бокс стал бы меньше минимума, отбрасывается.

Кандидаты меряются один раз, на нажатии (`snap_arm`). За жест ничего, кроме
перетаскиваемого, не двигается, а пересчёт на каждом `pointermove` стоил бы
принудительной раскладки на соседа на кадр. Внутри авто-раскладки списки остаются
пустыми: там драг про порядок, а не про координаты, и липнуть не к чему.

Направляющая — тонкая красная линия через весь лист в месте прилипания. Рядом с
ней розовые линейки с числом пикселей до ближайшего соседа с каждой из четырёх
сторон; соседом считается тот, кто стоит напротив — перекрывается по другой оси.
`Alt` над чужим элементом без всякого драга показывает расстояния между
выделенным и им: там условие «напротив» снимается, вопрос задан про конкретный
элемент, а не про окрестность.

Всё это рисуется в `Overlay` — слое рядом с `World`, а не внутри него. Мир
масштабируется трансформом, и линия в нём на 25% зума стала бы четвертью пикселя,
а подпись — нечитаемой. Оверлей живёт в экранных пикселях, а координаты листа
переводит `screen_x` / `screen_y`.

Рамка группы во время жеста берёт бокс из `drag_box`, а не меряет элементы заново:
шейпы и рамка — независимые атомы, и порядок их перерисовки ничем не задан, так
что замер отставал бы на кадр.

## Контекстное меню

Правая кнопка открывает меню над тем, на что нажали, и заодно выделяет этот
элемент, если он ещё не выделен — иначе меню говорило бы про то, чего не видно.
Пункты: дублировать, на передний план, на задний план, обернуть во фрейм, удалить.
По пустому месту меню не открывается: предлагать там нечего.

Нажатие правой кнопки в `pointer_down` выходит до `preventDefault` и до захвата
указателя: `contextmenu` приходит следующим событием и должен застать страницу
нетронутой. Захват вдобавок перецелил бы `click` на канвас, и пункт меню никогда
бы о нажатии не узнал — по той же причине нажатия внутри `[figmol_menu]`
обрабатываются мимо жестов.

Закрывает меню слушатель на `window`, а не канвас: клик в инспектор канвас не
видит, а меню закрыть надо.

«На передний план» и «на задний» — это порядок в `Kids`: элементы рисуются в том
порядке, в котором перечислены, никакого z-index нет и генератору переносить
нечего. Несколько выделенных поднимаются начиная с самого нижнего, так что их
порядок между собой сохраняется.

«Обернуть во фрейм» кладёт новый фрейм на общий бокс выделенного и переносит всё
внутрь, сохраняя места. Фрейм получается со свободным размещением, а не с
авто-раскладкой: раскладка была бы полезнее, но она тут же перекомпоновала бы
расставленное руками — не то, что человек имеет в виду, нажимая «обернуть».
Включить её — один клик в инспекторе. Обернуть можно только элементы одного
фрейма: бокс считается в его координатах, а у нод внутри авто-раскладки своих
координат нет.

## Хоткеи

- `⌘Z` / `Ctrl+Z` — отменить, `⌘⇧Z` / `Ctrl+Y` — повторить
- `⌘D` — дублировать выделенное вместе с поддеревом
- стрелки — сдвиг на 1px, с Shift на 10px (не для нод внутри авто-раскладки)
- `Escape` — снять выделение, `Delete` / `Backspace` — удалить выделенное
- `⇧1` — вписать страницу в окно, `⌘0` — сто процентов, `⌘+` / `⌘-` — ступени
  зума к центру вьюпорта

Слушатель висит на `window`, а не на `$mol_hotkey` корня: плагин слушает DOM-узел
своего view, а на холодной загрузке фокус на `<body>` — выше приложения, и до
него событие не доходит. Тот же слушатель закрывает inline-редактор подписи по
клику вне его: канвас видит только те нажатия, что попали в канвас. Зум работает
и без прав на запись — это про «посмотреть», а не про «поменять».

Пробел канвас слушает своим слушателем на `window`: тянуться к пробелу до того,
как взяться за мышь, — весь смысл жеста, а `keydown` до канваса дойдёт только
когда фокус уже в нём. Уход из окна с зажатым пробелом ловится через `blur`,
иначе вернуться можно было бы в канвас, который панорамирует и не
останавливается.
